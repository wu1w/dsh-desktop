# DSH 长期运行启动器

双击打包目录中的 `DSH-长期运行.command`，通过终端窗口启动 DSH。需要守护整个桌面进程时，每次都从这个入口打开，并让该终端进程保持运行。直接打开 `DSH.app` 仍可使用应用内部的引擎恢复与任务恢复，但没有外层进程守护。

启动器只运行同一应用包中的 DSH 可执行文件。它使用包内 Electron 的 Node 模式执行守护代码，再清除 `ELECTRON_RUN_AS_NODE` 环境变量启动正常桌面应用。不需要额外安装 Node，也不会安装登录项、launchd 服务或系统计划任务。

- DSH 以非零状态退出或被异常信号结束时，等待 1、2、4、8、16、30 秒重新启动；连续失败后保持最多每 30 秒一次。某次运行持续至少 60 秒后，退避计数重新开始。
- DSH 正常退出（退出码 0）后，启动器也结束。通过菜单主动退出不会被自动重新打开。
- 在启动器终端按 `Ctrl+C` 或结束启动器时，先向它自己创建的 DSH 子进程发送 `SIGTERM`；5 秒未退出则只向该子进程发送 `SIGKILL`，再等待最多 2 秒确认。不按进程名查杀，也不会终止其他 DSH、Codex 或用户进程。
- 如果已经直接打开了 DSH，新的桌面子进程会遵守 DSH 的单实例检查并正常退出，启动器随之结束。先正常退出已有 DSH，再从长期运行入口启动，才能由此启动器负责整个桌面进程的崩溃重启。

如果操作系统拒绝终止，或在上述确认期限内仍未报告子进程退出，启动器会明确报错、取消全部重启计时，并继续保留该子进程的归属和守护锁，直到收到真实退出事件。它不会把一次 kill/IPC 错误当作进程已退出，也不会在无法核实时启动第二个实例。此时终端可能继续等待，需检查操作系统中的该次启动；启动器不会扩大为全局查杀。

守护锁位于独立 DSH 数据目录中的 `desktop-supervisor.lock`，与应用自身的数据锁分离。默认目录为 `~/Library/Application Support/DSH-Codex/client`；设置 `DSH_CLIENT_DATA_DIR` 时使用该目录。原 Codex、DSH、Claude 的配置目录仍受保护。重复启动器被拒绝；失锁后停止自己的子进程，不接管其他实例的数据锁。异常终止可能留下短暂租约，默认过期时间为 30 秒，之后才允许重新取得锁。

启动器为自己的桌面子进程设置 `DSH_PROCESS_SUPERVISED=1`。在此模式下，应用启动失败会清理后以非零状态退出，让守护启动器继续退避重试；例如崩溃后应用数据锁的短暂租约尚未过期。应用原有数据锁及保护检查仍然保留，启动器不会删除或抢占这些锁。正常退出仍以状态 0 结束守护。

启动器语言使用 `DSH_LOCALE`，否则采用终端的 `LC_ALL`、`LC_MESSAGES`、`LANG`；支持中文和英文，其他语言回退英文。例如 `DSH_LOCALE=zh-CN`。应用内语言设置保持独立。

机器断电、操作系统崩溃、用户注销、启动器自身被强制结束或主动休眠时，不能继续执行任务。这个入口不会在开机后自动运行，也不会取消用户明确发出的休眠请求。唤醒或重新启动后需确保启动器仍在运行，或重新打开该入口。运行中的应用只能在系统允许唤醒执行的情况下恢复连接与任务。

进程重新拉起不等于盲目重发任务：任务仍由应用内的持久记录、原生执行历史核对及恢复策略决定是否继续。不能核实的执行结果保留为待核实；用户停止的任务不会因为重新启动而自行续跑。

## 验证

`node --test test/process-supervisor.test.mjs` 使用系统临时目录和自有测试子进程，覆盖连续崩溃、正常退出、信号退出、退避上限、稳定窗口重置、终止忽略 SIGTERM 的子进程、启动器收到信号、重复锁及失锁停止。测试不启动用户的桌面应用，也不读取凭据。
